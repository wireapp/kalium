HTTP request and response logs now record `host/path?query`. The scheme, port, user info and fragment are dropped. A Wire-owned host (`wire.com`, `wire.link`, `zinfra.io` and their subdomains) stays in clear. Any other host is a customer backend and keeps 3 characters (`ngi***`), or logs as `{}` when it is no longer than its hint. Path segments made of lowercase letters and hyphens, such as `conversations`, and version segments such as `v9` stay readable. Every other segment is obfuscated with the logger's existing rules: a domain keeps 3 characters (`ant***`) and an ID or asset key keeps 7 (`9a1d6c0***`). A segment no longer than its hint is logged as `{}`. The paging values `size`, `page`, `limit` and `offset` stay in clear when they are only ASCII digits. `client`, `cursor` and `since` keep their first 3 characters as a hint, such as `client=5f2***`. Every other query value, including `code`, `key`, `sig` and tokens, is logged as `***`. The push token in `push/tokens/{token}` is fully masked. `cursor` and `client` values are no longer logged in clear.

  - ABI: no change
  - Source: no change
  - Behavior: log lines change from `nginz-https.example.com/v5/users/example.com/<id>?client=<id>&size=20` to `ngi***/v5/users/exa***/9a1d6c0***?client=5f2***&size=20` for a customer host. A Wire host such as `nginz-https.anta.wire.link` stays in clear. Update log parsers or dashboards that read the `endpoint` field.
