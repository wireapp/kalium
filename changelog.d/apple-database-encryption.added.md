Added SQLCipher encryption for the global and user databases on Apple, as on Android, for an app and its extensions sharing them.

  - ABI: changed for the Apple `databaseDriver`, which takes an optional `passphrase`, and for the Apple `PlatformUserStorageProperties` constructor, which takes the user database secret; Kalium constructs it itself. `PassphraseStorage` has a new `setPassphraseIfAbsent`.
  - Source: breaking for direct callers of the Apple `PlatformUserStorageProperties` constructor, which now requires `userDbSecretProvider`, for callers passing the Apple `databaseDriver` `config` block positionally instead of as a trailing lambda, and for implementations of `PassphraseStorage`.
  - Behavior: with `KaliumConfigs.shouldEncryptData()`, the databases are encrypted with raw keys kept in the Keychain. Their first 32 bytes stay readable, so iOS recognizes them as SQLite databases in WAL mode and doesn't terminate a suspended app holding one in a shared App Group container; the SQLCipher salt is derived from the key. The global database uses WAL on Apple too. A new key is only ever added to the Keychain, never written over one stored in between, so the processes sharing it all use the first one stored, and an existing database whose key is missing fails to open instead of getting a new key. SQLCipher comes with CoreCrypto's library; Kalium refuses to open an encrypted database if the SQLite in the process isn't SQLCipher.
  - Migration: databases that earlier versions stored unencrypted on Apple are not migrated and fail to open. No production install has one; development installs need their app data cleared.
