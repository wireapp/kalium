# NSE coverage and remaining dependencies

The branch receives events through prepared Apple accounts, the shared ordered
Events queue, owned crypto transactions and one SQL effects transaction per
notification. Integration is described in [the NSE README](../nse/README.md);
[ADR 11](adr/0011-nse-account-runtime-ownership.md) records ownership and replay.

This is the current behavior inventory. The evidence column includes historical
native and Swift/app reports from the implementation; it does not claim that every
suite was rerun for the latest edit. Generated reports live under
`nse/build/reports/`. The test sources and scenario runner are the reproducible
entry points; historical progress narratives and abandoned designs live in Git.

**Supported** means the listed effects are implemented. **Pending/blocked** means
the whole notification and later queue remain pending until the named dependency
is resolved. Optional UI state and exact system-message history do not impose
that barrier. Actual APNs/host integration, signing, protected-data/device budgets,
Nomad and backup workflows are outside this library coverage. Legal-hold effects
remain intentional NSE no-ops, as do typing indicators, remote mute and in-call
emoji. These signals are excluded from required live-consumer work. Delivered-alert
updates and missed-alert recovery remain optional.

The no-op policy applies to signal effects. Encrypted remote mute and in-call emoji
still pass through common decryption and replay handling. Both are recorded as
application conversation dependencies, so a later destructive event in the same
notification can still trigger the existing replay guard. Typing is skipped at
DTO dispatch and adds no such dependency. Typing preference property updates are
separate durable settings and remain supported.

## Native contracts that constrain receiving

- **CoreCrypto 10.4.0 transactions:** the wrapper runs under `NonCancellable`.
  Returning `Either.Left` commits; required failures must throw. Receiving restores
  its attempt context inside the callback and awaits native unwind before closing
  or unlocking. An in-flight native operation is not promised to be interruptible.
- **Separate stores:** SQL can commit before native crypto, and MLS can commit
  before Proteus. Wiping a group or deleting its SQL identity can destroy the
  input needed for retry. Those deletion/reset/metadata guards remain necessary.
  Optional proposal commits use the existing app scheduler, because an external
  response cannot be reconstructed after the SQL/native gap.
- **Required establishment/recovery:** an external commit can succeed remotely
  before local failure; replay needs the returned events/welcome. Legacy teammate
  creation similarly needs an idempotent backend operation or authenticated
  reconciliation. A fresh POST with a new random conversation ID is not a retry.
- **MLS failure typing:** `Other` includes both malformed input and provider/store
  failures, so it cannot safely become a failed-message row. Wrong-epoch and
  foreign-group recovery can produce different plaintext after later epoch changes.
  Native unmerged external groups have no verified app-consumer handoff here.
- **Opening existing stores:** CoreCrypto's exported database operation opens or
  creates and migrates. Readiness and file checks do not provide a strict native
  existing-only/no-migration guarantee. The prepared-account path accepts this
  limitation; a stricter native API remains follow-up work. See the pinned
  [database API](https://github.com/wireapp/core-crypto/blob/v10.4.0/crypto-ffi/src/database/mod.rs)
  and [connection implementation](https://github.com/wireapp/core-crypto/blob/v10.4.0/keystore/src/connection/mod.rs).
- **CRL refresh visibility:** saving a CRL does not replace earlier in-memory
  sources or clear native certificate-status caches. An already-used environment
  can retain VALID status; a fresh environment reads the saved revocation.
  Immediate visibility needs native source replacement and status invalidation.
- **iOS binding mismatch:** 10.4.0 iOS archives enable `cancellable-transactions`,
  but the generated bindings use a host build without that feature. Rust inserts
  `TransactionCanceled = 5` and shifts `Other` to 6; KMP decodes `Other` at 5.
  The negative-control probe reproduced discriminant 6 with a missing entitlement.
  Native and generated feature sets must match; a decoder-only patch is insufficient.
  Pinned sources: [iOS flags](https://github.com/wireapp/core-crypto/blob/v10.4.0/make/config.mk),
  [KMP packaging](https://github.com/wireapp/core-crypto/blob/v10.4.0/crypto-ffi/bindings/kmp/build.gradle.kts),
  [error enum](https://github.com/wireapp/core-crypto/blob/v10.4.0/crypto-ffi/src/error/core_crypto.rs).
- **Calling artifact and lifecycle:** the pinned AVS 10.5.19 archive hash is
  `637e71bb26ae8d50446e500fd4141bcdb8ee4a13bc6bb1d861d6d656780e2d77`.
  App live handles register `wcall_set_shutdown_handler`, call `wcall_destroy`
  after cancelling and joining Kotlin work, and await native shutdown before
  disposing their callback references. In the pinned source, `instance_destroy`
  removes listeners and call resources, then `ide_handler` releases the marshal
  queue before invoking the shutdown handler. Cancelled waits preserve ownership
  for retry. This live-call teardown is separate from the NSE event API below.
  Match the locally inspected iOS `feat/avs_for_nse` implementation at
  `79ad8ca31d`: `create` registers a permanent account/client callback context;
  `end` evaluates a batch and does not destroy that handle. The Apple wrapper
  retains that context and routes each serialized batch to its request callbacks.
  Recreating the same native identity with a new context is an invalid wrapper
  lifetime assumption, not evidence that the artifact must be replaced.
  Device/simulator slices lack `APP_EXTENSION_SAFE`; device imports `UIApplication`
  and contains `sharedApplication`. These whole-artifact observations do not prove
  that the four event functions execute extension-forbidden code. Extension-mode
  linking succeeds; signed-device validation remains separate. Multi-conversation
  probes (both shared and distinct session IDs) return two incoming callbacks and
  one close for start A/start B/end B. Preserve AVS callbacks and test host routing;
  this observation alone does not establish a replacement-artifact requirement.
- **Call presentation after sync:** call JSON and conversation checks run inside
  the notification's required effects. Only committed signals enter the final AVS
  batch. As in the iOS branch, AVS errors are best effort and later call payloads
  still run; the host awaits incoming/close reports, with missed callbacks closing
  a ring only if that conversation rang during the request. This does not create
  persistent call-history rows or promise exactly-once CallKit delivery. Process
  exit/cancellation after processed markers, or native duplicate replay after a
  commit gap, can lose a call presentation. Earlier processed notifications remain
  processed if later receiving fails. No call outcome journal or recovery queue is
  introduced; MLS subconversation receiving remains a separate blocked path.
- **Terminal cleanup:** current-client/self-account removal can delete readiness,
  crypto-opening inputs and Events itself. There is no durable cleanup consumer
  that can re-enter after partial removal. This needs a terminal reconciliation
  contract; an ordinary message retry cannot supply it.
- **Device evidence:** simulator fixtures do not establish APNs delivery, real
  extension/host lifecycle, shared protected Keychain access or signed-device budgets.
  CoreCrypto WAL keys also depend on the default Keychain group and exact store path.

## Verification entry points

- [Native receiving tests](../domain/messaging/receiving/src/appleTest/kotlin/com/wire/kalium/logic/sync/receiving/NotificationProcessorNativeTest.kt)
  exercise real stores, ordered payloads, SQL/native/marker gaps, storage failures,
  cancellation, queue completion and subsequent ciphertext. Each selected native
  test is run in a fresh process; scenario counts may overlap in historical reports.
- [Swift/app runner](../nse/scripts/verify-swift-receiving.py) prepares real accounts,
  runs the production Swift facade, then reopens them through actual app consumers.
  Run it with `--help` for the supported mutually exclusive scenarios.
- Ownership, readiness, existing-database, network-close and crypto-close tests live
  beside those components. Their failure-retention and cancellation coverage remains
  separate from message-policy tests.
- [AVS event probe](../nse/scripts/verify-avs-event-api.py) records executable artifact
  findings under `nse/build/reports/avs-event-api/`; host integration is verified
  separately by the receiving tests and Swift/app runner.

The cleanup's replay tests explicitly accept extra access, promotion and connection
warning messages after interruption. They also cover access-before-fetch behavior:
on the first attempt an absent conversation cannot be updated; on retry the event
updates the now-stored row, so access may differ from the first fetched snapshot.
Actual field writes and crypto/storage integrity remain required.

Meeting invite, update and cancellation cards are ephemeral app-session notifications.
They are delivered only to active observers of that account. NSE meeting effects
remain durable and silent, following ADR 0011; no meeting-card queue or replay
store is added. Conversation notification types and the bulk meeting deletion
API remain available to existing consumers.
